# Evaluation results

Generated by `npm run eval:report` from the raw runs in [`runs/`](runs/). Every number below comes from those files.

Metrics: **valid schema** (output parses with the Zod schema), **score in range** (match score inside the labelled range), **missing-skill recall** (labelled must-detect gaps that were reported), **cases with false gaps** (a skill the CV has, or an alternative the CV already satisfies, reported as missing), **split OR groups** (an "A or B" requirement reported as several separate gaps), **gap precision** / **match precision** (reported gaps / matches that appear in the job text).

Notes:

- `0-baseline-metrics-v1` was the first run with only the first four metrics; it scored 100% on all of them, so the metrics and labels were extended (alternatives, grounding) before the real baseline `1-baseline`.
- The "OR group" failure was found by reading the raw dev outputs. The held-out cases `ho-11` and `ho-12` were written after that, but before any held-out run, to test whether the fix generalises.
- Each configuration was run once (single sample per case), so small score differences between runs are normal LLM variance.
